# DO-160G 规则文件编写说明

> 本文件是规则库的使用说明，不是审查规则。上传规则时请排除 `README.md`，仅上传按本说明编写的编号规则文件。

## 1. 文件命名与目录顺序

规则文件使用“二位数字序号-中文主题.md”命名，序号表示规则文件在本目录中的组织顺序，不等同于文件内部的规则编号。当前目录约定如下：

| 文件范围 | 内容与用途 |
| --- | --- |
| `README.md` | 规则编写说明，不上传、不参与审查 |
| `01-跨章一致性.md` | 全文结构和跨章节一致性规则 |
| `02-试验项目一览表一致性.md` | 试验项目一览表与正文的一致性规则 |
| `03-通用章节检查项.md` | 第一个试验项目章节之前的通用章节规则 |
| `04-*.md`～`26-*.md` | DO-160G 各标准试验项目章节规则 |
| `27-加速度.md` | 加速度环境专项规则；判据框架来自QTP检查单，DO-160G依据为第7章持续载荷程序 |
| `28-风车环境.md` | 风车环境专项规则；DO-160G依据为第8章短时高量级振动程序 |
| `29-试验记录与报告.md` | 试验记录、终止恢复、报告和记录类规则 |

新建文件时使用当前未占用的下一顺序号，序号固定为两位数字；中文主题应能准确说明规则对象。不得通过改名复用已有规则文件或规则编号。若新增的是某一现有试验章节的规则，应优先加入对应的 `04`～`26` 文件，不另建重复主题文件。

## 2. 文件内部的规则编号

文件名序号只负责目录排序，规则编号用于系统识别和结果追踪，两者不要混用。规则编号必须在整个规则库中唯一。

| 规则组 | 编号格式 | 示例 |
| --- | --- | --- |
| 跨章一致性 | `QTP-XREF-两位序号` | `QTP-XREF-01` |
| 试验项目一览表 | `QTP-LIST-两位序号` | `QTP-LIST-01` |
| 通用章节 | `QTP-GEN-两位序号` | `QTP-GEN-01` |
| DO-160G 试验章节 | `QTP-DO160G-标准章号-两位序号` | `QTP-DO160G-04-01` |
| 加速度环境专项 | `QTP-ACC-两位序号` | `QTP-ACC-01` |
| 风车环境专项 | `QTP-WMV-两位序号` | `QTP-WMV-01` |
| 记录与报告 | `QTP-REC-两位序号` | `QTP-REC-01` |

每个规则文件内部从 `01` 开始连续编号，不跳号、不重号。每条规则使用二级标题，标题序号与该文件内规则编号的末两位保持一致，例如二级标题“01. 测试设备名称与型号完整性”对应编号 `QTP-DO160G-04-01`。

## 3. 规则类型及应用范围

系统按规则类型决定规则被送往哪个文档区域。类型必须选择准确，不能依靠关键词弥补错误的类型。

| 填写值 | 系统值 | 应用范围 | 使用要点 |
| --- | --- | --- | --- |
| 通用章节 | `general_chapter` | 仅应用于封面、目录及第一个试验项目章节之前合并形成的通用章节段 | 适用于目的、范围、引用文件、术语、验证条款、设备描述、试验概述、通用要求、承试单位、人员、组织分工、功能检查等；关键词不参与路由，通常省略 |
| 试验项目章节 | `test_item_chapter` | 仅应用于由“试验概述”识别出的试验项目一级章节 | 必须保留 1～2 个高辨识度的试验名称或必要标题变体，使规则只进入对应试验章节；留空会应用到全部试验项目章节 |
| 专项章节 | `section_specific` | 仅应用于标题命中“关键词”或“适用章节”的章节 | 适用于试验记录、终止恢复、报告要求、记录等固定主题章；保留 1～2 个高辨识度标题词或必要变体 |
| 文档级 | `document_specific` | 逐章审查结束后，在全文汇总阶段执行一次 | 关键词不决定规则是否执行，只用于选择候选原文；内容一致性规则保留 1～2 个证据检索词，纯目录或顺序规则可省略 |
| 全局 | `global` | 应用于每一个文档切片 | 只用于确实对所有切片成立的文字质量或通用表达要求；关键词不参与路由，通常省略 |
| 输出 | `output` | 当前调度行为与全局规则相同 | 仅供系统级输出约束使用，不建议用于普通业务检查；关键词不参与路由，通常省略 |

04～28 各试验文件中，第 01～05 条是每个试验章节都必须检查的测试设备/系统规则；其规则类型仍为“试验项目章节”，并使用本文件对应试验项目的关键词，使其只进入正确的试验章节。27、28的目录号不等同于DO-160G章号，其规则编号分别使用 `QTP-ACC-*` 和 `QTP-WMV-*`，且在规则说明中写明真实标准条款来源。

## 4. 单条规则的结构

一个编号规则必须只产生一个独立审查结果。规则块依次包含以下信息：

| 项目 | 编写要求 |
| --- | --- |
| 二级标题 | 使用“两位序号. 规则名称”，名称应直接说明检查对象和要求 |
| 规则编号 | 按第 2 节格式填写，库内唯一 |
| 规则类型 | 只能使用第 3 节列出的类型名称或系统值 |
| 文档类型 | 填写该规则适用的文档类型，例如“试验大纲” |
| 关键词 | 可选且含义随规则类型变化：文档级为 1～2 个证据检索词；试验项目/专项为 1～2 个章节匹配词；通用章节、全局和输出通常省略 |
| 规则说明 | 用一句话说明检查对象、合格条件和主要失败条件 |
| 审查内容 | 列出必须核查的对象、字段、参数、表格或证据来源 |
| 审查步骤 | 给出可执行的定位、比对、判定和输出步骤 |

实际规则文件应在元数据之后分别设置“审查内容”和“审查步骤”两个三级标题，并保持现有文件格式一致。不要把多项互不依赖、需要分别返回结论的检查合并为一条规则；应拆成多个编号规则。

## 5. 规则描述规范

- 明确审查对象和当前文档区域，例如“本试验章节”“试验概述表”“全文目录”，避免只写“检查是否符合要求”。
- 明确合格所需的字段、参数、单位、允差、状态或证据，不能只引用 DO-160G 条款号而不展开判定条件。
- 明确证据来源及比对关系。跨章节、跨表格或依赖完整目录的检查应使用“文档级”，不要写成逐章规则。
- 明确结论条件：证据完整且满足要求判 `Pass`；确认缺少或不符合强制要求判 `Fail`；因扫描质量、图表无法解析、条件是否适用不明确或证据不足而无法可靠判断时判 `Review`。
- 每条规则都必须返回结果。不得因“不适用”、未找到目标或证据不足而静默跳过；应按规则定义返回 `Pass`、`Fail` 或 `Review`，并说明依据。
- 需要逐项核查的规则必须输出全部不符合项，不得只返回第一处错误；可合并列出已符合项以控制输出长度。
- 关键词必须按规则类型控制：文档级只保留 1～2 个有助于选择原文的证据检索词，纯目录/顺序规则可省略；试验项目章节和专项章节只保留 1～2 个高辨识度标题匹配词；通用章节、全局和输出规则通常不填写。不得使用过宽的单字或通用词。
- 规则说明、审查内容和步骤之间应保持一致，不得出现标题检查 A、步骤却检查 B 的情况。

## 6. 上传与更新注意事项

- 上传时排除本 `README.md`。编号规则文件应保持 UTF-8 编码和 `.md` 扩展名。
- 修改既有规则内容时，使用系统的替换/更新方式，避免同一规则编号产生重复记录。
- 文件改名不会自动清除数据库中以旧 `sourceFile` 保存的规则。本次调整后，如系统中已上传过旧文件，应先删除或停用来源为 `00-跨章一致性.md`、`01-试验项目一览表一致性.md`、`02-通用章节检查项.md`、`03-各章测试设备.md` 的旧记录，再上传新文件。
- 原 `03-各章测试设备.md` 不再作为规则文件。测试设备/系统的五项通用要求已经分别嵌入 `04`～`26` 各试验章节文件的第 01～05 条。

## 7. 发布前检查清单

1. 文件名使用两位数字序号且目录内不重号；说明文件只有 `README.md`。
2. 文件内规则标题和规则编号均从 `01` 连续递增，规则编号全库唯一。
3. 每条规则均填写正确的规则类型，应用范围与关键词设置一致。
4. 每条规则只有一个独立结论，并明确 `Pass`、`Fail`、`Review` 的触发条件。
5. 文档级规则具备跨章证据要求；逐章规则不会要求模型读取当前切片之外的内容。
6. 逐项检查会返回全部错误，缺失证据时也会返回审查结果。
7. 上传前已排除 `README.md`，并处理数据库中的旧文件来源记录。
